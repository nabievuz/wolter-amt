## Step 0A — Live write’dan oldingi majburiy isbot

**HG-F6-03 oldin, HG-F6-06 undan keyin, HG-F6-01 eng oxirida.** Kill, restore va schema-aware rollback’ni real takeover’dan keyinga qoldirib bo‘lmaydi. Drill’lar AMT PC’dagi izolyatsiyalangan `restore_drill` konteynerida (systemd-nspawn, root; lokal snapshot `--bind-ro` bilan; `--private-network` — tarmoq yo‘q; o‘z mount, PID va network namespace’lari, o‘z `/run`, `/var/lib` va PostgreSQL klasteri, `sandbox` slice; ichida Docker yo‘q — Langfuse omborlari (PostgreSQL, ClickHouse, MinIO) bir xil pinned versiyadagi oddiy jarayonlar, AMT servislari ichida unit sifatida fixture’larga qarshi ishlaydi; live credential, job va egress’siz; production control socket’i va kill latch’i mount qilinmaydi; production `control_epoch` va kill latch mashqdan oldin va keyin bir xil bo‘lishi shart; `killed` rejimda boshlanadi) — [KILL_SWITCH](../06_Runbooks/KILL_SWITCH.md), [BACKUP_RESTORE](../06_Runbooks/BACKUP_RESTORE.md) §4, [UPGRADE](../06_Runbooks/UPGRADE.md), [RUN_RESUME](../06_Runbooks/RUN_RESUME.md) bo‘yicha:

1. **Kill.** `restore_drill` konteynerida fixture’larda, konteyner ichidagi simulyatsiya qilingan Meta endpoint’iga qarshi A/B kill race, LLM/media latch, dispatcher epoch, partial remote result va in-flight reconciliation; Telegram/DB yo‘qligi ham fixture’da sinaladi. B rejimi har managed entity’ning eng yuqori to‘liq managed darajasini pauza qiladi, foreign parent’ga tegmaydi. Vaqtlar `ops.kill_targets` chegaralari bilan o‘lchanadi (⧗ OD-11). SSH kill yo‘li mashq ichida kill bilan sinalmaydi: uni production’da owner Tailscale orqali SSH bilan bajargan `sudo /opt/wolter-amt/current/bin/amt-kill --self-test` isbotlaydi — rejim o‘zgarmaydi (◇ P-12). Owner tasdiqlagan PAUSED Meta test integratsiyasi (F6-AT-08 (2)) production’da global `shadow` rejimida, F3-AT-05 dagi `origin=test` PAUSED-fixture istisnosi bo‘yicha (production credential’lari, faqat PAUSED test entity), Step 1 dan oldin bajariladi — hech qachon `staging` yoki `restore_drill` da emas; aktivlashtirish simulyatsiya; faqat B kill ishlatadigan pauza chaqiruvi `origin=test` item orqali sinaladi, production kill bajarilmaydi — production `control_epoch` va kill latch o‘zgarmaydi.
2. **To‘liq restore** lokal snapshot’dan: host PostgreSQL (AMT workflow ledger bilan; Paperclip `amt` dan qayta sinxronlanadi), Langfuse’ning o‘z PG + ClickHouse + MinIO (ortiqcha blob qabul qilinadi), config/sirlar/kalitlar; **landing custody va Umami restore** — production Dokploy hostidagi izolyatsiyalangan restore target’ga (owner, HG-F2-18); jonli DB ustiga hech qachon. Host yo‘qolishi stsenariysida manbalardan qayta qurish owner chiqargan PII’siz manba eksportidan (landing receipt metadata’si va amoCRM events eksporti, read-only fayllar); CAPI qayta yuborish konteyner ichidagi sintetik endpoint’ga, host-loss qoidasi bilan — dedup’ga tayanilmaydi (`operations.yaml#host_loss.rebuild_from_sources`). Restore har doim `killed` rejimda boshlanadi (◇ P-16); `shadow` + L0 ga faqat reconcile’dan keyin owner qadami bilan o‘tiladi; live credential, job va egress’siz. Resume darajasi `min(snapshot rejimi, off-host control journal’dagi oxirgi rejim, L1)`; journal mavjud bo‘lmasa barcha pipeline L0 va owner har birini alohida ochadi. Tartib: read/ingest → remote reconciliation → consent-valid CAPI backfill → tracking gate → owner resume.
3. **Schema-aware rollback** haqiqiy migratsiya bilan mos code/config/schema snapshot’idan; yangi schema ustiga eski binary’ni yoqish yetarli emas. Migratsiya yoki rollback paytida kelgan submit, consent withdrawal va webhook saqlanadi (EVO-AT07); upgrade davomida kill, host yo‘qolishi yoki operator javobsizligi (EVO-AT12). Accepted intake va remote `uncertain` attempt yo‘qolmasligi tekshiriladi.
4. **RPO/RTO.** Har data class uchun tasdiqlangan target va o‘lchangan natija (`recovery.full_datasets`, `recovery.restore_check` — P30D, `recovery.full_drill` — P92D); mantiqiy xato uchun umumiy RPO ≤24 soat (ma’lumot yo‘qotish oynasi: xato paytidagi eng yangi tugallangan, MANIFEST tekshirilgan lokal recovery point’dan xatogacha. `operations.yaml#rpo_readiness_rule` bo‘yicha interval + completion/scheduling delay va failed/missed run holatlaridagi eng katta yaroqli point yoshi o‘lchanadi; kundalik run o‘zi ≤24 soatni isbotlamaydi. Kerak bo‘lsa shu diskda qisqaroq snapshot intervali yoki local WAL/PITR ishlatiladi; isbot bo‘lmaguncha readiness pending). Process-crash, disk ko‘chirish va host yo‘qolishi alohida baholanadi. Zaxira PC yo‘q (Q55), shuning uchun host yo‘qolishidagi biznes tiklash vaqti **komponentlar yig‘indisi**, har komponent `measured` yoki `estimated` deb belgilanadi: F0 o‘rnatish va bootstrap vaqti `build` rejimida haqiqiy PC’da — yangi PC yo‘lining eng yaqin o‘lchangan proksisi; `--rebuild` farqi (owner bajaradigan BACKUP_RESTORE §5.1 skriptlari, deploy key’larni qayta qo‘shish, `git verify-tag`) — ixtiyoriy mashq bajarilgan bo‘lsa o‘lchanadi, aks holda taxmin qilinadi va dalilda `estimated` deb belgilanadi (`host_loss_time_seconds.rebuild_delta.method`) (tavsiya, owner hal qiladi: F2 live intake’dan oldin, production ma’lumoti yo‘qligida, haqiqiy PC’da bitta owner bajaradigan `--rebuild` + §5.1 mashqi), kalit, tunnel va Tailscale qadamlari — o‘lchangan yoki tabletop’da taxmin qilingan (`keys_tunnel.method`) (age qog‘oz/QR nusxasi — Q56, writer fence, `sops rotate`; real rotatsiya production’ni buzadigan joyda bir martalik sinov resurslarida yoki tabletop), `restore_drill` da staged eksportdan o‘lchangan qayta qurish va validation vaqti va amoCRM tarixini rate limit’li API orqali o‘qish vaqti (hisoblanadi — `source_fetch`, `estimated`). Yig‘indi `recovery.full_datasets` dagi tasdiqlangan host-loss target ichida bo‘lmasa yoki boshqa mezonga erishilmasa Step 1 blocker.
5. **Operator drill.** Primary/deputy qamrovi, off-host monitor host, bot va Telegram yo‘qolishini ham aniqlaydi va alternate kanal ishlaydi (`ops.independent_monitor_full`), severity ACK/eskalatsiya va owner yo‘q paytidagi xavfsiz holat (faqat himoya nazoratlari) real mashqda tasdiqlanadi. Operator incident ACK huquqi owner-only kill/rol/birinchi aktivlashtirish huquqiga aylanmaydi; deputy kill qila olmaydi (⧗ OD-04).
6. **Pul.** `vendor.meta_cap` va shu kungi read-back (`budget.ads_fresh_check`, P1D); verified MTD, pending va safety margin; `protective_pause` sinovi; faol kampaniyalar sarfiga himoya (UAT-17, UAT-18). Provider spending limit majburiy (Q37 ✅), protective pause faqat qo‘shimcha.

Shundan keyin builder faqat sandbox → verification → owner release yo‘lidan foydalanadi ([SELF_EVOLUTION](../03_Architecture/SELF_EVOLUTION.md)); vaqtinchalik yordam faqat HG-OPS-02.
