# F0 — Production server va tiklash poydevori

Holat: spetsifikatsiya · Runtime: NOT_RUN · Sana: 2026-10-23.

## Maqsad
Owner’ning Toshkent ofisidagi PC’sida (`amt-pc`; Q52, [ADR-032](../04_ADR/ADR-032-owner-pc-office-host.md)) xavfsiz va qayta tiklanadigan AMT host tayyorlanadi ([ADR-033](../04_ADR/ADR-033-tunnel-tailscale-omada-access.md)):
- kiruvchi port ochilmaydi; `mar`, `mar2`, `mar3` faqat Cloudflare Tunnel orqali (Q57);
- SSH faqat Tailscale orqali, faqat owner qurilmalaridan (Q58);
- PC ofis LAN’idan Omada VLAN/ACL bilan ajratilgan (Q59);
- RAID1 (Q52), UPS va elektr qaytganda o‘zi yonish (Q53);
- sirlar sops’da shifrlangan, disk shifrlanmagan (Q54); xotiradagi lead PII diskka tushmaydi (Q62);
- har kecha va har upgrade oldidan lokal snapshot (Q55).

F0 platforma qurilishi uchun poydevor beradi; production qabulini yoki real trafik ruxsatini bermaydi. `build/F0/EVIDENCE.md` bajarilgan dalilni, readiness reyestri esa hali ochiq talablarni ajratadi.

## Prerequisites

**Birinchi sessiya:** mavjud Ubuntu/Claude o‘rnatmasi, qisman init yoki user/huquq/katalog nomosligida [SERVER_ADOPTION](SERVER_ADOPTION.md) majburiy: avval faqat o‘qish preflight, keyin dalilga mos `adopt_existing` (joriy ofis PC’si) yoki alohida owner tanlagan fresh install. HG-F0-00 yopilmaguncha bootstrap bajarilgan deb taxmin qilinmaydi. Prerequisite’lar tasdiqlangach builder birinchi tekshirilmagan F0 vazifadan davom etadi; yangi bootstrap’dan keyin bu **3-vazifa**.

- Boshlash tartibi: HG-F0-01 (PC, BIOS, UPS) → HG-F0-07 (Omada, statik IP) → HG-F0-05 (repolar, `project-os/` push, `main` va tag rulesetlari, signer kaliti; builder deploy key’lari HG-F0-00 skripti so‘raganda qo‘shiladi) → HG-F0-03 (age public key) → HG-F0-04 (Tailscale siyosati, device approval, oldindan tasdiqlangan auth key) → HG-F0-00 (bootstrap) — [PHASES §4.2](PHASES.md).
- Faza ichida kerak bo‘ladi: HG-F0-02 (Cloudflare Tunnel va akkaunt himoyasi), HG-F0-08 (tashqi tekshiruv, F0 oxirida).
- Bootstrap bosqichidagi sirlar (masalan HG-F0-04 auth key) sops paydo bo‘lguncha (7-vazifa) faqat lokal konsol yoki Tailscale orqali SSH bilan serverga qo‘yiladi — chat yoki Telegram orqali emas.
- Jismoniy ish (o‘rnatish, disk uzish yoki almashtirish, elektr sinovi, BIOS) faqat owner (Q52); builder bunday qadamda `build/NEEDS_HUMAN.md` yozadi.

Har build/test toza eksportda bajariladi:
     ```bash
     set -o pipefail                      # a failed build must not look green through tee
     mkdir -p build/logs                  # relative to project_os_root

     sudo -u amt-build install -d -m 700 "/srv/amt-build/work/$run"
     ```

## Appendix B — `infra/bootstrap/external-check.sh` (HG-F0-08, owner ishga tushiradi)

Skriptni builder yozadi. Owner uni o‘z noutbukida ikki joydan ishga tushiradi:

- **Ofisdan tashqarida** (masalan mobil internet; noutbukda Tailscale yoqilgan): `MODE=outside OFFICE_PUBLIC_IP=<IP> OFFICE_WAN_IP=<ER605 WAN IP> ONT_WAN_IP=<ONT WAN IP, router rejimida bo‘lsa> AMT_TAILNET_IP=<IP> ./external-check.sh > f0-external-outside.txt`
  - NAT turi alohida qayd etiladi: WAN manzil `100.64.0.0/10` ichida yoki provayder CGNAT’ni tasdiqlasa — `skip (CGNAT)`; ONT router rejimida bo‘lsa (ikki qavatli NAT) — skanerlash baribir bajariladi, chunki ONT’dagi port forward ham ochiq port beradi; aks holda `nmap -Pn -p 1-65535 --open $OFFICE_PUBLIC_IP` → AMT’ga tegishli ochiq port yo‘q; topilgan har port qaysi qurilmaniki (ONT, ER605) ekani yoziladi (F0-AT-02);
  - `curl -s -o /dev/null -w '%{http_code}' https://mar.wolter.uz` → `503` (F0-AT-03, CF orqali);
  - `ssh -o BatchMode=yes root@$AMT_TAILNET_IP true` va `ssh -o PubkeyAuthentication=no -o BatchMode=yes owner@$AMT_TAILNET_IP true` → ikkalasi rad; xato xabarida faqat `publickey` usuli ko‘rinadi (F0-AT-05).
- **Ofis LAN’idan** (AMT VLAN’dan tashqarida; noutbukda `tailscale down`): `MODE=office_lan AMT_LAN_IP=<PC IP> ./external-check.sh > f0-external-lan.txt`
  - `nmap -Pn -p 1-65535 $AMT_LAN_IP` → hammasi `filtered` (F0-AT-02);
  - `ssh -o BatchMode=yes owner@$AMT_LAN_IP true` → rad (F0-AT-05);
  - `ping -c 3 $AMT_LAN_IP` va `nc -zv -w 5 $AMT_LAN_IP 22` → javob yo‘q (F0-AT-16).

Server tomonidagi qismni builder bajaradi: `ip -6 addr show dev <LAN NIC> scope global` → bo‘sh (F0-AT-02); `ss -ltnup` ruxsat ro‘yxati bilan solishtiriladi (F0-AT-03).

Natija `pass`/`fail`/`skip` qatorlari bilan chiqadi. Owner fayllarni Telegram’da builder’ga beradi (ops-bot F1’dan) yoki `build/F0/EVIDENCE.md` ga qo‘yadi.
