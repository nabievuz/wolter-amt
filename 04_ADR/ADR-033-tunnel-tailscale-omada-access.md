# ADR-033 — Kirish: Cloudflare Tunnel, Tailscale orqali SSH (sshd) va Omada LAN izolyatsiyasi

Holat: Accepted · Qaror egasi: owner (Q57, Q58, Q59, Q60, Q46.2, Q49 ✅) + builder ★ (Q34/Q46★, Caddy) · Sana: 2026-10-23

## Kontekst

- Owner qarorlari: `mar`, `mar2`, `mar3` faqat Cloudflare Tunnel orqali, kiruvchi port ochilmaydi — ofisda statik IP yo‘q (Uztelecom GPON 1 Gb/s); Cloudflare boshqa jihatdan faqat HTTPS proxy; Paperclip’dan faqat superadmin (owner) va u ruxsat bergan foydalanuvchilar foydalanadi (Q57). SSH faqat Tailscale orqali, faqat owner qurilmalaridan; AMT tuguni tailnet’dagi boshqa tugunlarga ulana olmaydi; faqat kalit, root login yo‘q (Q58). PC ofis tarmog‘idan Omada bilan ajratiladi: ER605 v2.0 + SG2428P v5.30, apparat controller OC200/OC300 (Q59). Zaxira internet hozircha yo‘q; bir oylik uzilish statistikasidan keyin qaror (Q60) [D: DECISION_LOG].
- O‘zgarmagan qarorlar: `mar2` — faqat webhook’lar, maxfiy yo‘l + imzo tekshiruvi (Q46.2); `mar3` — Langfuse UI (Q34/Q46★); 2FA Telegram orqali, tg-auth (Q49). Q57 bilan internetga ochiq port umuman qolmaydi.
- Paperclip `authenticated` rejimida 2026 boshida unauthenticated RCE (CVE-2026-41679, CVSS 10) bo‘lgan va tuzatilgan [D]; Paperclip’ni internetga ochish xavf darajasini oshiradi. `X-Forwarded-Host` endi `TRUST_PROXY` ni talab qiladi [D: Paperclip breaking changes].
- Tunnel origin IP’ni ochmaydi va kiruvchi portsiz ishlaydi, lekin ingress qoidasi xato yozilsa yoki Cloudflare akkaunti buzilib begona hostname qo‘shilsa hostdagi boshqa lokal servis tashqariga chiqib qolishi mumkin [X].
- Tunnel tokeni aylantirilgandan keyin mavjud connector’lar qayta ishga tushguncha ulangan qoladi [D: Cloudflare "Tunnel tokens" hujjati]: o‘g‘irlangan hostdagi `cloudflared` faqat token aylantirish bilan uzilmaydi.
- `ListenAddress` `tailscale0` manziliga bog‘lansa, manzil boot’da kech paydo bo‘lganda yoki tugun qayta autentifikatsiyada yangi IP olganda sshd tinglamay qoladi [X]; socket’ni manzilga emas, qurilmaga bog‘lash (`BindToDevice=`) bu muammoni bermaydi — systemd socket’ni shu qurilmaga `BindsTo=`/`After=` bilan bog‘laydi, qurilma yo‘qolsa socket to‘xtaydi, shuning uchun socket’ni qurilmaning o‘zi ishga tushirishi kerak (udev `SYSTEMD_WANTS` — qurilma faollashganda `Wants=` [D: systemd.device]); socket `sockets.target` dan boshlansa, boot qurilmani `DefaultDeviceTimeoutSec` (90 s) kutib qoladi, chunki `tailscale0` ni faqat `tailscaled` yaratadi, u esa `basic.target` dan keyin ishga tushadi [D: systemd.socket, systemd-system.conf]; `--netfilter-mode=on` da `tailscaled` `tailscale0` trafigini o‘zi qabul qiladi, shuning uchun u yerdagi ufw qoidasi haqiqiy filtr emas (F0-AT-21 tekshiradi) [T].
- Ofis LAN’ida boshqa qurilmalar bor: PC LAN’ga ochiq bo‘lsa buzilgan ofis qurilmasi AMT’ga, buzilgan AMT esa ofis qurilmalari va tarmoq boshqaruviga yetadi [X]. Tailnet’da owner qurilmalari ham bor: Tailscale siyosatisiz buzilgan AMT tuguni ularga ulana oladi [X].

## Qaror

1. **Ingress — faqat Cloudflare Tunnel** (`cloudflared`, o‘z UID’i, faqat chiquvchi ulanish — Cloudflare Tunnel edge, 7844). Tunnel masofadan boshqariladi (Zero Trust dashboard, HG-F0-02): public hostname’lar `mar.wolter.uz`, `mar2.wolter.uz`, `mar3.wolter.uz` → `http://127.0.0.1:8080`, oxirgi qoida `http_status:404`, boshqa hostname yo‘q. Kutilgan holat git’da — `infra/cloudflared/ingress.expected.yaml` (lokal `config.yml` ingress’i ishlatilmaydi); owner o‘z qurilmasidan faqat o‘qish huquqli API token bilan `GET /accounts/<id>/cfd_tunnel/<tunnel_id>/configurations` ni o‘qib git bilan solishtiradi (F0-AT-04). Servis: `cloudflared --no-autoupdate --metrics 127.0.0.1:20241 tunnel run`; tunnel tokeni sops’da, servisga faqat `EnvironmentFile=/run/amt/secrets/cloudflared.env` dagi `TUNNEL_TOKEN` sifatida beriladi — buyruq qatorida hech qachon. Per-UID nftables: `cloudflared` UID loopback’da faqat `127.0.0.1:8080` (Caddy) va DNS uchun systemd-resolved stub’i `127.0.0.53:53`/`127.0.0.54:53` (udp+tcp) ga, tashqariga faqat Cloudflare Tunnel edge’ining 7844 portiga (tcp+udp) yetadi — Cloudflare akkauntida qo‘shilgan begona hostname Paperclip (3100), Langfuse (3000) yoki boshqa lokal servisga yetmaydi; F0-AT-04 rad etilgan ulanishni va `sudo -u cloudflared getent hosts region1.v2.argotunnel.com` bilan DNS ishlashini tekshiradi. Cloudflare akkaunti himoyasi (HG-F0-02): 2FA, a’zolar ro‘yxatida faqat owner, keraksiz API token yo‘q; "Cloudflare Tunnel Write" huquqli API token owner’da qoladi, AMT PC’ga qo‘yilmaydi. Cloudflare boshqa jihatdan faqat HTTPS proxy; origin sertifikati, Authenticated Origin Pulls va Cloudflare IP allowlist kerak emas.
2. **Kiruvchi port yo‘q:** host firewall `ufw default deny incoming` (IPv4 va IPv6) LAN NIC’dagi har kiruvchi portni, shu jumladan 22 ni, yopadi. `ufw allow in on tailscale0 to any port 22 proto tcp` faqat niyatni yozadi: netfilter rejimi `on` da `tailscaled` `tailscale0` trafigini o‘zi qabul qiladi, shuning uchun tailnet’dagi filtr — Tailscale siyosati (5-band). Ruxsat etilgan listener’lar: loopback’dagi servislar (`127.0.0.0/8` va `::1`: Caddy 8080, `cloudflared` metrics `127.0.0.1:20241`, PostgreSQL 5432, systemd-resolved stub’i `127.0.0.53`/`127.0.0.54:53` va boshqa `127.0.0.1` servislari), sshd faqat `0.0.0.0%tailscale0:22` va `[::]%tailscale0:22` (5-band), `tailscaled` UDP 41641 va tailnet IP’lardagi peerAPI; staging konteyneri ishlayotgan paytda systemd-networkd’ning DHCP serveri faqat `ve-amt-staging` da (`0.0.0.0%ve-amt-staging:67`, UDP) — ruxsat etilgan istisno, ufw ham uni faqat shu veth’da ochadi; DHCP client, LLMNR va mDNS yo‘q; ephemeral portdagi client UDP soketlari (masalan `cloudflared` QUIC) listener hisoblanmaydi (F0-AT-03). AMT VLAN’da IPv6 o‘chiq; Omada’da AMT uchun port forward, virtual server, DMZ va UPnP yo‘q.
3. **Caddy 2** faqat `127.0.0.1:8080` da, tunnel ortida: `mar.wolter.uz` (Paperclip) va `mar3.wolter.uz` (Langfuse) uchun `forward_auth` → tg-auth (Q49); `mar3` da istisno `/api/public/*` (Langfuse ingest, API kalit bilan); `mar2.wolter.uz` da faqat `/amo/<secret>` va `/meta/<secret>` (imzo tekshiruvi bilan, Q46.2), qolgani 404. Global `servers { trusted_proxies static 127.0.0.1/32; client_ip_headers Cf-Connecting-Ip }`: mijozning haqiqiy IP’si log va tg-auth’ga (IP o‘zgarishi qoidasi, rate limit, login xabari) shu sarlavhadan o‘tadi, 127.0.0.1 emas (F1-AT-06). Telegram public yo‘li yo‘q: ops-bot lokal Bot API’dan foydalanadi, Telegram’ga faqat chiquvchi ulanish.
4. **Paperclip:** `authenticated` rejim, `TRUST_PROXY` faqat Caddy, `127.0.0.1` bind, `allowed-hostname mar.wolter.uz`; foydalanuvchilar — owner va u ruxsat bergan shaxslar (Q57, [ADR-018](ADR-018-rbac-registry.md)).
5. **SSH — faqat Tailscale orqali, oddiy sshd bilan (Q58):** Tailscale siyosati — [tailscale-policy.hujson](../09_Config_Templates/tailscale-policy.hujson) shabloni, builder uni `infra/tailscale/acl.hujson` sifatida commit qiladi: `tagOwners` (`tag:amt` ni faqat owner qo‘llaydi), yagona qoida owner → `tag:amt:22` (tcp), `tag:amt` manba bo‘lgan qoida yo‘q — AMT tuguni boshqa tailnet tuguniga ulana olmaydi, `ssh: []`, `tests` bloki (Tailscale testlari o‘tmagan siyosatni saqlamaydi). HG-F0-04 da owner siyosatni bir martalik `tag:amt` auth key yaratishdan **oldin** admin konsolga qo‘yadi va device approval’ni yoqadi; kalit **oldindan tasdiqlangan (pre-approved)** qilib yaratiladi — aks holda tasdiqlanmagan tugun trafik yubora olmaydi; o‘zgarish faqat PR va HG-F0-04 bilan (F0-AT-08). Tugun: `tailscale up --auth-key=file:<faqat root o‘qiydigan vaqtinchalik fayl> --advertise-tags=tag:amt --ssh=false --accept-dns=false --accept-routes=false`; qayta autentifikatsiyada (rotatsiya) yangi bir martalik, oldindan tasdiqlangan auth key bilan shu flag’larning hammasi va `--force-reauth` har safar yoziladi — flag’lar saqlanmaydi; auth key hech qachon buyruq qatorida emas. Tailscale SSH (Tailscale’ning o‘z SSH xizmati), exit node va subnet route o‘chiq; AMT tuguni key expiry’si o‘chirilgan (builder sozlamasi, HG-F0-04). sshd faqat `tailscale0` interfeysida (owner tasdiqlagan xulosa): `ListenAddress` yo‘q; `ssh.socket` drop-in’i `/etc/systemd/system/ssh.socket.d/10-tailscale0.conf` → `BindToDevice=tailscale0` — socket faqat `tailscale0` da tinglaydi — joriy noble paketidagi `ssh.socket` IPv4 va IPv6 uchun alohida `ListenStream` ochadi (`BindIPv6Only=ipv6-only`), shuning uchun `ss` ikki listener ko‘rsatadi: `0.0.0.0%tailscale0:22` va `[::]%tailscale0:22`; boshqa interfeysdan kelgan paket sshd’ga yetmaydi; `tailscale0` faqat `tailscaled` ishga tushgandan keyin paydo bo‘lgani uchun socket `sockets.target` dan ishga tushirilmaydi (`systemctl disable ssh.socket`; aks holda har boot qurilmani 90 s kutardi) — uni faqat qurilma ishga tushiradi: udev qoidasi `/etc/udev/rules.d/90-amt-tailscale0.rules` (`SUBSYSTEM=="net", KERNEL=="tailscale0", TAG+="systemd", ENV{SYSTEMD_WANTS}+="ssh.socket"`), `tailscale0` har paydo bo‘lganda (boot va `tailscaled` restart; qayta autentifikatsiya qurilmani qayta yaratmaydi). sshd mustaqil ishlamaydi: `ssh.service` drop-in’i `Requires=ssh.socket`/`After=ssh.socket` va `systemctl disable ssh.service` (mustaqil sshd `*:22` ga bog‘lanardi) (reboot, `tailscaled` restart va UPS sikli — F0-AT-21); LAN NIC’da ufw ikkinchi qatlam, tailnet’da filtr — Tailscale siyosati; qulflanib qolinsa — owner lokal konsoli ([BACKUP_RESTORE](../06_Runbooks/BACKUP_RESTORE.md) §6); faqat kalit, `PermitRootLogin no`, `AllowUsers owner builder` (builder HG-F6-06 da olinadi). Telegram ishlamasa owner `amt-kill` ni shu yo‘l bilan bajaradi ([ADR-030](ADR-030-kill-modes-and-protective-controls.md)).
6. `cloudflared`, `tailscaled` va `sshd` `control` slice’ida ishlaydi ([runtime-isolation.yaml](../09_Config_Templates/runtime-isolation.yaml) `services`); `tailscaled` holat fayli `/var/lib/tailscale/tailscaled.state` (root 0600). Tunnel tokeni va Tailscale tugun kaliti `ops.credential_inventory` da. **Writer fence** (PC yoki disk o‘g‘irlanishi, INC-26, [ADR-032](ADR-032-owner-pc-office-host.md)): tunnel tokenini aylantirish ishlab turgan connector’ni uzmagani uchun owner o‘z qurilmasidan (1) Tailscale admin konsolida eski AMT tugunini olib tashlaydi; (2) Zero Trust dashboard’da tunnel tokenini aylantiradi ("Rotate token"); (3) "Cloudflare Tunnel Write" huquqli token bilan `DELETE /accounts/<id>/cfd_tunnel/<tunnel_id>/connections` orqali barcha mavjud ulanishlarni uzadi; (4) yangi tokenni yangi hostga qo‘yadi; (5) `GET …/connections` faqat yangi host connector’ini ko‘rsatishini tekshiradi.
7. **LAN izolyatsiyasi — Omada (Q59):** AMT o‘z VLAN’ida; SG2428P’dagi PC porti shu VLAN’ning untagged access porti yoki PC ER605 portiga to‘g‘ridan ulanadi. PC’da statik IPv4 (DHCP yo‘q: gateway boshqaruv ACL’i DHCP unicast yangilanishini ham to‘sadi); DNS `1.1.1.1` va `9.9.9.9` statik netplan’da, gateway faqat default route. ER605 ACL: AMT ↔ ofis LAN ikki tomonga deny; AMT tarmog‘i uchun "Gateway Management Page" ACL — gateway’ning barcha interfeys IP’lariga (AMT VLAN gateway manzili ham) AMT’dan paket deny, routing ishlayveradi; switch va controller ACL — AMT → SG2428P va controller boshqaruv IP’lari deny; AMT → internet allow (HG-F0-07). F0-AT-16 shu manzillarda 22, 80, 443, 8043 va Omada portlarini sinaydi. Controller hech qachon AMT PC’da ishlamaydi.
8. **Internet (Q60):** zaxira liniya hozircha yo‘q; uzilishlar F0 qabul qilingan kundan bir oy `/var/log/amt/outage.jsonl` ga qayd etiladi (`operations.yaml#outage_log`; HG-F2-17 dan mustaqil monitor ham manba), keyin owner qaror qiladi. ER605 ikkinchi WAN’ni qo‘llaydi; tunnel chiquvchi bo‘lgani uchun WAN almashuvida uning sozlamasi o‘zgarmaydi.
9. F0 dalili: tunnel ingress validatsiyasi, kiruvchi port yo‘qligi, SSH rad holatlari va LAN izolyatsiyasi owner’ning ofisdan tashqaridan va ofis LAN’idan bajargan tekshiruvi bilan (HG-F0-08; F0-AT-02, F0-AT-03, F0-AT-04, F0-AT-05, F0-AT-08, F0-AT-16); reboot, `tailscaled` restart, UPS sikli va tugun qayta autentifikatsiyasidan keyingi SSH (faqat `%tailscale0:22` listener’lari) va firewall jadvallarining birga turishi — F0-AT-21.

## Ko‘rib chiqilgan variantlar

| Variant | Nega tanlanmadi |
|---|---|
| Statik IP va ochiq 443/22 port | ofisda statik IP yo‘q (Q57); tunnel kiruvchi portsiz ishlaydi |
| Statik IP’li VPS orqali WireGuard relay | qo‘shimcha host va oylik to‘lov; amalda baribir tunnel (Q57) |
| Cloudflare Access (SSH uchun) | owner SSH uchun Tailscale’ni tanlagan (Q58); Paperclip 2FA — Telegram (Q49) |
| SSH faqat ofis LAN’idan | ofisdan tashqarida masofaviy kirish yo‘q; owner ofisda bo‘lmasa Telegram’siz `amt-kill` yo‘li yo‘q |
| Traefik | owner Dokploy’dan biladi, lekin `forward_auth` va oddiy konfiguratsiya uchun Caddy tanlangan ★ |

## Oqibatlar

- **+** Internetga ochiq port yo‘q: origin IP’ni skanerlash yoki Cloudflare’ni chetlab o‘tish yo‘li yo‘q; Cloudflare WAF va DDoS himoyasi saqlanadi.
- **+** Statik IP kerak emas: tunnel va Tailscale faqat chiquvchi ulanish ochadi; WAN almashsa tunnel sozlamasi o‘zgarmaydi.
- **+** Buzilgan AMT tuguni ofis LAN’i, Omada boshqaruvi va owner qurilmalariga yeta olmaydi (VLAN/ACL va Tailscale siyosati).
- **−** Kirish Cloudflare va Tailscale xizmatlariga bog‘liq: tunnel uzilsa `mar`, `mar2`, `mar3` ishlamaydi — landing intake production Dokploy’da davom etadi (I08), uzilishni host’dan mustaqil monitor aniqlaydi (`ops.independent_monitor`); Tailscale ishlamasa masofaviy SSH yo‘q, Telegram kill yo‘li va owner’ning jismoniy kirishi qoladi.
- **−** Zaxira internet yo‘q (Q60): ofis interneti uzilsa AMT tashqi dunyodan uziladi; reklama provider spending limit va inson custody’sida qoladi.
- **−** `tailscaled` root huquqidagi vendor daemon va egress’i toraytirilmaydigan yagona root servis (ixtiyoriy peer’larga UDP); Tailscale SSH o‘chiq, kirish faqat sshd orqali.
- **−** Tunnel tokeni va Tailscale tugun kaliti shifrlanmagan diskda (Q54) — o‘g‘irlikda darhol 6-banddagi writer fence va rotatsiya (INC-26).
- **−** Cloudflare akkaunti buzilsa hujumchi begona hostname qo‘shishi, ingress’ni o‘zgartirishi yoki tunnel’ni o‘chirishi mumkin: begona hostname faqat Caddy’ga (`127.0.0.1:8080`) yetadi va Caddy faqat `mar*` ni tg-auth bilan xizmat qiladi, Paperclip, Langfuse va boshqa lokal servislar to‘g‘ridan ochilmaydi; `mar*` kirishi baribir hujumchi nazoratida qolishi mumkin [X] — shuning uchun akkaunt himoyasi (HG-F0-02), F0-AT-04 read-back’i va buzilishda 6-banddagi token aylantirish va ulanishlarni uzish.
